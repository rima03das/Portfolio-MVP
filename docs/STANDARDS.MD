# Follow these coding standards

- Naming Conventions. Use descriptive, pronounceable names for variables, functions, and classes. Common casing rules include camelCase for local variables and functions, PascalCase for classes, and UPPER_SNAKE_CASE for constants.
- Indentation and Formatting. Apply consistent spacing (typically 2 or 4 spaces rather than tabs) to show code nesting clearly. Keep line lengths within a fixed limit, such as 80 to 120 characters, and use blank lines to separate distinct logical blocks.
- Comments and Documentation. Write clear comments that explain why a complex decision was made rather than repeating what the code already shows. Include standard headers at the top of files or modules detailing the author, creation date, and purpose.
- Function and File Organization. Keep functions short and focused on a single task to simplify testing and debugging. Group related files into a predictable directory structure.
- Unused Code. Don't comment unused code. Delete it.
